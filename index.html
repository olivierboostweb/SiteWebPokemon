PokéQuest 90s: présentation du site web

Cette page sert de support d'oral et de tableau de bord. Les raccourcis permettent de passer directement aux autres parties du site pendant la démonstration.

Accueil Générations Collection Ajouter une carte Infos DB
Plan conseillé: introduction, objectifs, démonstration de navigation, gestion des cartes, base de données, hébergement Vercel, conclusion.
01

Introduction du projet

PokéQuest 90s est un site web inspiré des anciens sites Internet. Il présente une collection de cartes Pokémon avec une interface rétro, colorée et volontairement nostalgique.

Ouvrir l'accueil
Durée: 45 secondes. Présenter le nom, le thème Pokémon et l'ambiance années 90.
02

Objectifs principaux

Le site a été conçu pour montrer une collection de cartes, mais aussi pour prouver qu'une page web peut communiquer avec une vraie base de données modifiable.

  • Consulter les cartes par génération.
  • Rechercher une carte dans la collection.
  • Ajouter, modifier et supprimer des données.
Voir les générations Voir toutes les cartes
Durée: 1 minute. Expliquer que le site n'est pas seulement décoratif: il est connecté à une base.
03

Navigation et expérience

L'utilisateur peut naviguer avec les onglets du haut ou le menu latéral. Chaque partie correspond à une action claire: explorer, consulter, ajouter ou comprendre la base.

Navigation rapide Aperçu de carte Recherche
Démontrer la recherche
Durée: 1 à 2 minutes. Cliquer sur la collection, utiliser la recherche, puis ouvrir l'aperçu d'une carte.
04

Structure des données

Les informations sont séparées en plusieurs tables. Cette organisation rend le projet plus propre et permet de relier une carte à sa série, son booster, sa rareté et sa génération.

generation serie booster rarete tbl_carte
Voir les infos DB
Durée: 1 à 2 minutes. Décrire les tables et expliquer que la carte est l'élément central.
05

Gestion des cartes

La collection peut évoluer directement depuis l'interface. Le formulaire envoie les informations à l'API, puis l'API les enregistre dans PostgreSQL.

  • Ajout d'une carte avec formulaire.
  • Modification depuis l'aperçu.
  • Suppression si une entrée est incorrecte.
Ouvrir le formulaire Modifier depuis une carte
Durée: 1 à 2 minutes. Montrer le formulaire, puis expliquer que les boutons Modifier/Supprimer sont dans l'aperçu.
06

Fonctionnement technique

Le site affiché dans le navigateur communique avec une API serverless. Cette API reçoit les demandes, interroge la base Neon PostgreSQL, puis renvoie les données au site.

Interface /api PostgreSQL
Durée: 1 minute. Expliquer le chemin: clic utilisateur, API, base de données, retour sur la page.
07

Déploiement en ligne

Le projet est prévu pour être hébergé sur Vercel. La base de données reste séparée du site, ce qui permet de garder les informations même après un redéploiement.

  • Vercel héberge le site et l'API.
  • Neon héberge la base PostgreSQL.
  • Les variables d'environnement connectent les deux.
Durée: 1 minute. Dire que le site peut être consulté en ligne et que les données restent persistantes.
08

Conclusion

PokéQuest 90s combine un style rétro, une navigation simple, une vraie base de données et une interface de gestion. Le projet peut évoluer avec des comptes utilisateurs, un système d'upload d'images et des filtres plus avancés.

Retour accueil Revenir à la présentation
Durée: 45 secondes. Résumer le projet, rappeler les points forts et terminer avec les améliorations possibles.
